## Review-3 攻击目标

### T1: Bootstrap Protocol 正确性

**攻击方向**：证明 Bootstrap Protocol B1-B6 仍然存在循环依赖，或冷启动场景下 Authority 无法产生。

**关键问题**：
- Gate 运行是否真的不需要 Authority？
- record_validation_event 返回 None（pending_review）时，Authority 不存在，Admission fail-closed → 这是否是正确行为？
- 多 claim 场景：部分 claim 有 Authority，部分没有，如何处理？

### T2: Run Identity Model 正确性

**攻击方向**：证明 run_id 不是冗余的，或 Run A/B replay 场景存在状态机冲突。

**关键问题**：
- candidate_id 是否真的全局唯一？（UUID 碰撞概率？）
- 同一 Document 在同一 Run 中重试（attempt_id），是否创建新 Candidate？
- Authority 不跨 Candidate 转移——如果同一 Document 的两个 Candidate 都 approved，是否有重复物化风险？

### T3: Issuer Contract 最小约束有效性

**攻击方向**：证明 Issuer Contract C1-C7 不足以防止 Authority 冒充或伪造。

**关键问题**：
- H2/H3 约束（validator 前缀检查）是否可绕过？
- human_review 的 validator 不以 "gate/" 开头——如何防止 human 冒充另一个 human？
- validation_method 是枚举，但 validator 是自由字符串——是否有注入风险？

### T4: AuthorityIdentity 三元组充分性

**攻击方向**：证明 (source_version_id, candidate_id, claim_id) 不足以唯一标识 Authority，或存在跨 Document 转移风险。

**关键问题**：
- source_version_id 是否可能为 None？
- claim_id 在同一 Candidate 内是否唯一？
- 跨 Document 场景：Document A 的 Authority 能否被 Document B 使用？

### T5: 两层 enforcement 独立性（继承 Rev-1）

**攻击方向**：证明 IR Boundary 和 Admission Boundary 仍然可能共享同一 evaluate decision，导致重复检查而非纵深防御。

**关键问题**：
- IR Boundary 检查什么？Admission Boundary 检查什么？
- 两层检查的 failure mode 是否真的不同？
- 如果 IR Boundary 通过但 Admission Boundary 拒绝，状态机如何处理？

### T6: 与 20 §8.2 双入口兼容性

**攻击方向**：证明 Authority enforcement 破坏 20 §8.2 冻结的双入口定义。

**关键问题**：
- auto path：gate_decision=auto_approve → Admission.approve()
- human path：review_trail 含 human/golden approve → Admission.approve()
- Authority enforcement 是否改变这两个入口的语义？
- 物化事务是否被 Authority 检查破坏？
